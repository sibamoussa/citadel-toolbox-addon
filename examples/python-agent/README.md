# Python Agent Consumer

This example runs a Microsoft Agent Framework hosted agent that discovers and invokes tools from
an existing Citadel Toolbox. It supports the governed **APIM route** and an optional direct Foundry
connection. New setup files default to APIM. It demonstrates callable tools, not automatic loading
of attached skills from MCP Resources.

```text
Model requests: Agent -- developer/workload Entra identity --> Foundry model
Tool requests:  Agent -- APIM subscription key --> APIM -- managed identity --> Foundry Toolbox
```

## Configure

From the repository root, run:

```powershell
./examples/python-agent/Setup.ps1
```

Setup installs the tested SDK versions and creates an ignored `.env` beside the example. It does
not overwrite an existing `.env`. For an older installation, add the APIM settings below explicitly.
You can edit that file locally, or supply environment variables through your hosting secret store.
Existing process environment variables take precedence over `.env` values.

### Connect Through APIM

1. Complete [Part 1 and Part 2](../../README.md#part-2-register-the-toolbox-in-apim): publish the
  Toolbox, register its full backend endpoint in APIM, and grant APIM's managed identity access to
  the Foundry project. Confirm APIM can reach the backend and response buffering/logging is disabled.
2. In APIM, open **Subscriptions**, create a subscription scoped to the registered **API**, and
  securely obtain its primary or secondary key. Use a separate subscription for each consumer.
  Creating or registering the MCP API does not automatically create a consumer subscription.
3. Configure the example with the gateway URL printed by registration, ending in
  `/citadel-toolbox/mcp`. Use your configured path or custom gateway domain when different.

```dotenv
FOUNDRY_PROJECT_ENDPOINT=https://<account>.services.ai.azure.com/api/projects/<project>
AZURE_AI_MODEL_DEPLOYMENT_NAME=<model-deployment-name>
TOOLBOX_CONNECTION_MODE=apim
TOOLBOX_ENDPOINT=https://<apim-name>.azure-api.net/citadel-toolbox/mcp
APIM_SUBSCRIPTION_KEY=<api-scoped-subscription-key>
```

`FOUNDRY_PROJECT_ENDPOINT` is still the **model's** project, not the gateway URL. `TOOLBOX_ENDPOINT`
is now APIM's agent-facing MCP endpoint, not the Foundry backend. Do not append `api-version` or put
the subscription key in its query string. APIM's backend policy supplies Foundry-specific headers,
the configured API version, and its own Entra token.

The agent's `DefaultAzureCredential` identity needs model access in its Foundry project. APIM's
managed identity separately needs permission to invoke the Toolbox in the backend project, which
may be different. The agent does not need direct Toolbox access for this route. The subscription
key authorizes APIM access; it does not authenticate to the model. This example targets the
subscription-key policy generated by Part 2, not arbitrary OAuth/JWT gateway policies.

The key is a secret. Do not commit it, put it in prompts, send it to the browser, or print it in
logs. Use a secret injection mechanism in hosting and rotate keys using APIM's primary/secondary
key pair. APIM's shared backend identity is not delegated user authentication; do not enable Work IQ
or user-specific operations assuming the end user's permissions are forwarded.

### Optional Direct Foundry Connection

For Part 1 validation without APIM:

```dotenv
TOOLBOX_CONNECTION_MODE=foundry
TOOLBOX_ENDPOINT=https://<account>.services.ai.azure.com/api/projects/<project>/toolboxes/<toolbox-name>/mcp?api-version=v1
```

Keep the model settings above. `APIM_SUBSCRIPTION_KEY` is unused in direct mode and can be removed.
The developer/workload identity now needs both model and Toolbox access. The helper uses
`FoundryToolbox(credential, url=endpoint)` for direct Entra authentication. For backward compatibility,
an absent `TOOLBOX_CONNECTION_MODE` also selects `foundry`; an unknown value fails immediately.

### What the Code Does

[toolbox_connection.py](toolbox_connection.py) validates configuration and selects the client. The
APIM branch uses the verified Agent Framework API:

```python
toolbox = MCPStreamableHTTPTool(
   name="citadel-toolbox",
   url=endpoint,
   static_headers={"Ocp-Apim-Subscription-Key": subscription_key},
   load_prompts=False,
)
```

Prompts are disabled because APIM does not support MCP prompts. In [main.py](main.py),
`async with toolbox` initializes the MCP connection and loads tools before handing them to
`Agent(..., tools=toolbox)`. The session stays open while `ResponsesHostServer` runs and is closed
on shutdown or failure. No Foundry bearer token is attached by the APIM client. APIM validates the
subscription and replaces backend authentication with its managed-identity token.

This example targets the default read-only Toolbox. Do not enable state-changing tools until the
agent runtime has a real approval handler; instructions and `require_approval` metadata alone do not
block tool execution. An APIM API name or subscription does not make an action-enabled Toolbox
read-only. Use a backend containing only the tools that this consumer is authorized to call.

Attached skills need explicit resource discovery, reading, and skill-loading logic. This example
does not inject those resources into the model's instructions in either connection mode.

## Run

In VS Code, press **F5** and select **Debug Citadel Toolbox Agent Example**. Foundry Toolkit opens
Agent Inspector after the Responses server starts. Try:

```text
What tools can you use? Find the relevant policy for my request and cite its source.
```

You can also start the server directly:

```powershell
./examples/python-agent/.venv/Scripts/python.exe ./examples/python-agent/main.py
```

The example always loads its own `.env`, regardless of the current directory. Existing `.env`
values are left unchanged by setup; if the host still connects directly, check the selected mode
and any overriding process environment variables. Press **F5** for interactive Agent Inspector
testing once the gateway configuration is ready.

## Verify and Troubleshoot

First verify initialization and tool discovery through the gateway, then make a known read-only
request and compare it with Part 1's direct results. An invalid APIM subscription key must fail.
Check APIM diagnostics for the correct API/backend without recording secrets or MCP payloads.
Starting the Responses host verifies discovery, not the outcome of every tool or model call.

| Symptom | Check |
| --- | --- |
| Configuration error before startup | Mode is `apim`, gateway endpoint is HTTPS without query parameters, and the key is not empty or a placeholder. |
| APIM 401/403 | Subscription is active and scoped to the correct API; inspect any inherited authorization policies. |
| Backend 401/403 | APIM's system-assigned identity, Foundry token audience, project RBAC, and connection permissions. |
| Model authorization failure | Agent developer/workload identity and model project access, independent of the APIM key. |
| 404 | Gateway path and final `/mcp`, not the original Foundry URL. |
| Timeout or discovery failure | APIM-to-Foundry networking, response buffering/logging, and MCP compatibility. |
| Tools work but skills are missing | Skills are MCP Resources; this example only wires callable tools. |

Run the offline example tests from the repository root:

```powershell
./examples/python-agent/.venv/Scripts/python.exe -m unittest discover -s examples/python-agent -p test_toolbox_connection.py -v
```

The tests cover client selection, rejected configuration, session cleanup, and a real in-process
Streamable HTTP MCP exchange with subscription headers, discovery, and invocation. They use no
Azure credentials or network calls and do not establish that a live APIM deployment is configured.

## Browser Demo

After the agent server is listening on port 8088, start the standalone demo UI from the repository
root in a second terminal:

```powershell
./examples/python-agent/.venv/Scripts/python.exe ./examples/python-agent/demo-ui/server.py
```

Open `http://127.0.0.1:8090`. The local UI server serves the static chat interface and proxies only
readiness and Responses API requests to the agent, so Foundry credentials and Toolbox endpoints are
never sent to the browser. Conversation context remains in the browser and agent requests use
`store: false`.

No credentials are embedded in source code. `DefaultAzureCredential` uses the developer identity
locally and the assigned workload identity when hosted. The APIM key stays in the server process
and its secret configuration, never the demo browser.
